# CanIRunAI

**你的 Mac，能跑多聪明的 AI？**

[打开网页版](https://sggg221.github.io/CanIRunAI/)。面向 Apple Silicon Mac 的模型选型、自动设备检测、模型部署与本地聊天工具。

## 网页 + 本地助手

网页不是云端推理服务。**首次启动并配对本地助手后**，网页才能自动检测本机、下载模型和进行真实图文聊天；未连接时仍可浏览目录或展开手动评估。

1. 在 Apple Silicon Mac 安装 Node.js 24（最低 22.13）。
2. 从网页下载 **新版 Mac 本地助手**，解压后双击 `Start CanIRunAI Helper.command`。
3. 保持助手终端打开。助手会打开带一次性配对码的网页；按浏览器提示允许本地网络访问。未自动连接时，输入终端中的 8 位配对码。
4. 网页显示真实设备配置，按这些数据重新评估模型。点击模型的 **一键部署**，确认下载；缺少运行环境或切换模型时，页面会请求相应的额外同意。
5. 在工作台查看下载、校验、启动、暂停/继续及失败信息。模型就绪后即可进行流式文字或图片聊天，也可停止或删除已安装模型。

详细安装、配对与故障排查见 [助手说明](docs/HELPER.md)。助手仍需要 Node.js，并不是签名、公证的独立 macOS `.app`。网页不能跳过首次安装、系统许可或配对。

### 已实现

- 中文响应式页面，适配桌面、平板和手机。
- 沿用原项目 27 个精选模型、15 个系列，支持搜索、分类、排序与适配筛选。
- 配对后自动读取真实硬件、可用内存、磁盘与 Ollama 状态；资源状态定期更新。未知信息明确标为未知，其他平台明确拒绝模型部署。
- 使用实机配置的推荐、运行时兼容性预检、固定模型摘要校验与真实部署进度。
- 确认后启动已有 Ollama；无法启动已有环境时才安装固定校验值的运行时。**正在运行的旧版外部 Ollama 不会被网页强制替换**，需在本机更新并重启。
- 已安装模型启动/停止/删除，下载暂停/恢复/取消，失败原因与日志。
- 本地流式聊天、停止生成；视觉模型支持上传/粘贴 PNG、JPEG、WebP 图片，复用原项目的图片压缩、体积和数量限制。
- 会话续期、刷新恢复配对、断开并撤销授权、过期/离线提示；不会在授权丢失后继续提交部署链。
- 未连接时保留手动评估。默认 16 GB 总内存、12 GiB 可用内存、100 GiB 磁盘只是示例，不是设备检测结果。

### 隐私与安全边界

- 本机助手只监听 `127.0.0.1:31415`，不公开到网络。不配置云模型密钥，也不上传硬件或聊天到网站服务器。
- 只有允许的 Origin 可以配对，接口要求绑定 Origin 的短期令牌，并检查 Host、防止任意命令输入。GitHub Pages 的信任边界是 **`https://sggg221.github.io` 整个 Origin**，不能按 `/CanIRunAI/` 路径隔离其他同源网页。
- 配对码仅放在 URL fragment，网页读取后立即移除，不通过查询参数发送到 Pages。令牌仅存放在当前标签页的 `sessionStorage`，不放入分享链接。
- 分享配置使用片段链接，拿到链接的人能看到所分享的内存/磁盘数值。聊天记录不持久保存，刷新、断开连接或切换聊天模型会清空当前聊天。
- 模型与运行时下载需要网络；其来源及校验由助手管理。浏览器可能要求本地网络许可，具体兼容性取决于版本和设备管理策略。不要关闭浏览器安全保护来连接。

## 开发与构建

构建建议 Node.js 24；助手打包额外使用 Python 3（只要求构建机安装，Mac 助手用户不需要 Python）。

```bash
npm ci
npm --prefix apps/site ci
npm run helper:package # 生成开发网页中的助手下载文件
npm run site:dev       # http://localhost:5173
```

在另一个终端启动源码中的助手：

```bash
npm run helper
```

开发时在本地网页输入终端显示的配对码。助手启动时默认打开公网网页，而不是开发地址。

```bash
npm test
npm run check
npm run site:build     # 先打包匹配源码的助手，再进行网页类型检查与生产构建
npm run site:preview
```

`apps/site/dist/` 是静态站点，包含 `downloads/CanIRunAI-Helper.zip`。服务器不运行 Bridge；**只有下载并在用户电脑上启动的助手才执行本机操作**。纯目录浏览无需助手、数据库或 API 服务。请使用 HTTP(S) 访问，不要双击构建后的 `index.html`。

## 发布网站

参见 [部署说明](docs/DEPLOYMENT.md)。GitHub Actions 的 Website 工作流会在 PR / main 提交时检查并构建，只有手动选择 `main` 并勾选 `deploy` 才发布。

- GitHub 仓库 Settings → Pages → Source：GitHub Actions。
- Actions → Website → Run workflow：选择 `main`，勾选 `deploy`。
- 其他静态托管平台：构建 `npm ci && npm --prefix apps/site ci && npm run site:build`，输出 `apps/site/dist`，提供 Node.js 24 与 Python 3。
- 只部署输出目录。其中的助手 ZIP 是刻意公开的源代码运行包，不包含依赖安装目录、模型权重、聊天、会话令牌或本机状态。

每次修改助手或协议后应一并重新构建并发布网站，让下载包与页面匹配。原 ZIP 不会自动更新。

## 验证范围

自动测试覆盖模型推荐、协议与安全、真实 HTTP 配对和授权轮换、部署状态机、图文协议及流式输出、配置分享，以及助手 ZIP 的确定性、权限、独立安装和启动。

**自动测试中的 Mac 设备和 Ollama 推理可以是明确的测试替身，不等于 Mac 真机测量。** 本次开发环境为 Linux，真实助手可读出实际 Linux 硬件并正确禁用部署；无法据此宣称已验证 macOS 首次打开/Gatekeeper、Apple Silicon 真实模型下载、Metal 推理或所有浏览器的本地网络许可。

目录不承诺全量或实时更新。历史“元数据核验 / 推理测试”标签不代表当前用户设备实测；实际部署仍以固定摘要和运行时预检为准。原交付的历史验证记录保留在 [VALIDATION.md](VALIDATION.md)。
